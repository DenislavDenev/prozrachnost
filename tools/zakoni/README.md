# Закони и решения

Какво приема Министерският съвет и какво е на обществено обсъждане: регистърът на актовете на Министерския съвет
(постановления, решения, разпореждания, от 1946 г.), всички обществени консултации от 2008 г. със срока им и мотива за
по-кратък срок, стратегическите документи (национални, областни, общински) и договорите за оценка на въздействието.
Всяко число води до набора на data.egov.bg, от който е, и има дата на четене.

Порт 8013. Част от [Прозрачност](https://github.com/DenislavDenev/prozrachnost). Лиценз на данните: CC-BY (условия 2 на
data.egov.bg; Администрация на Министерския съвет), проверен на 02.10.2026.

## Страници

| Адрес | Какво |
|---|---|
| `/` | изречение (колко акта тази седмица, колко консултации са отворени, колко от тях със срок под 30 дни), актове по седмици, отворени консултации; `?na=ГГГГ-ММ-ДД` показва деня както е бил |
| `/karta` | карта на общинските консултации по общини и области (брой, със срок под 30 дни, дял), по години |
| `/aktove`, `/aktove/<pris_id>` | регистърът на актовете с търсене, вид, година, вносител, брой на ДВ; един акт със свързаните актове, консултацията му и историята на промените |
| `/konsultacii`, `/konsultacii/<номер>` | консултациите с филтри (ниво, вид акт, област на политика, срок, област и община, отворени на ден); една консултация със срока, мотива и документите |
| `/strategii` | стратегическите документи с филтри и „действащи на ден“ |
| `/sravnenie?a=2025&b=2020` | една и съща сметка за два периода (година, месец или `от:до`) |
| `/tarsene?q=` | търсене в заглавията на актове, консултации и стратегии |
| `/sources`, `/sources.json`, `/how` | наборите, свежестта, сверките; как работи |
| `….csv`, `….json` | всеки списък има CSV и JSON със същия обхват и филтри (`/aktove.csv?year=2024`, `/konsultacii.json?short=da`) |

## Данни

Как е построено, подробно в [docs/methodology.md](docs/methodology.md) и [docs/sources.md](docs/sources.md):

1. **бронз**: файловете на архива „Наблюдател“ (`/opt/tender/arhiv/egov/18da0fff-…/`), по sha256; инструментът само ги чете;
2. **сребро** (`silver`): типизирани таблици с формата на източника, версионни (`valid_from`, `valid_to`), всеки ред с хеша на файла;
3. **злато** (`gold`): актове, консултации, стратегии и договори с ключа на източника (`pris_id`, номер `-K`), срок в дни, индикатор за кратък срок, община, връзки между набори; ред без ключ отива в `gold.unmatched`;
4. проверки (`db/checks/*.sql`), сверки на броя, дневник на промените (`ops.change_log`);
5. страници, CSV и JSON над златото.

Не се пазят имена на коментиращи, лица за контакт, имейл адреси и имена на физически лица в договорите.

## Стъпки

```bash
python -m ingest.run --step migrate     # схемите
python -m ingest.run --step build       # архив -> сребро -> сверки -> злато -> проверки (около 560 MB JSON, стрийминг)
python -m ingest.run --step freshness   # какво е закъсняло, задържано или счупено
```

Разписание (UTC, общият workflow „Прозрачност“): `build` всеки ден в 04:30, свежест в 09:20 и 21:20. Тихо, когато всичко е наред.

## Тестове

```bash
pip install -r requirements.txt httpx2
python -m pytest -q                                   # парсерите и стрийминга (без база)
ZAKONI_TEST_DSN=dbname=zakoni_test python -m pytest -q   # и базата, страниците (отделна база; името трябва да съдържа test)
ZAKONI_TEST_DSN=dbname=zakoni_test python tests/mutations.py   # всяко правило, което пази данните, се чупи нарочно
```

Фикстурите в `tests/fixtures/egov/` са истински записи от файловете на архива от 02.10.2026, съкратени; личните полета са заменени.
