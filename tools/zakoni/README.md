# Закони и решения

Какво приема Министерският съвет и какво е на обществено обсъждане: регистърът на актовете на Министерския съвет
(постановления, решения, разпореждания, от 1946 г.), всички обществени консултации от 2008 г. със срока им и мотива за
по-кратък срок, стратегическите документи (национални, областни, общински) и договорите за оценка на въздействието.
Всяко число води до набора на data.egov.bg, от който е, и има дата на четене.

Порт 8013. Част от [Прозрачност](https://github.com/DenislavDenev/prozrachnost). Лиценз на данните: CC-BY (условия 2 на
data.egov.bg; Администрация на Министерския съвет), проверен на 02.10.2026.

## Страници

| Адрес | Какво |
|---|---|
| `/` | изречение (колко акта тази седмица, колко консултации са отворени, колко от тях със срок под 30 дни), актове по седмици, отворени консултации; `?na=ГГГГ-ММ-ДД` показва деня както е бил |
| `/karta` | карта на общинските консултации по общини и области (брой, със срок под 30 дни, дял), по години |
| `/aktove`, `/aktove/<pris_id>` | регистърът на актовете с търсене, вид, година, вносител, брой на ДВ; един акт със свързаните актове, консултацията му и историята на промените |
| `/konsultacii`, `/konsultacii/<номер>` | консултациите с филтри (ниво, вид акт, област на политика, срок, област и община, отворени на ден); една консултация със срока, мотива и документите |
| `/strategii` | стратегическите документи с филтри и „действащи на ден“ |
| `/sravnenie?a=2025&b=2020` | една и съща сметка за два периода (година, месец или `от:до`) |
| `/tarsene?q=` | търсене в заглавията на актове, консултации и стратегии |
| `/sources`, `/sources.json`, `/how` | наборите, свежестта, сверките; как работи |
| `….csv`, `….json` | всеки списък има CSV и JSON със същия обхват и филтри (`/aktove.csv?year=2024`, `/konsultacii.json?short=da`) |

## Данни

От 24.11.2026 данните са в общата база `prozrachnost` ([tools/danni](../danni/README.md)), по образеца на Население.
Как е построено, подробно в [docs/methodology.md](docs/methodology.md) и [docs/sources.md](docs/sources.md):

1. **сурово**: файловете на архива „Наблюдател“ (`/srv/prozrachnost/nablyudatel/egov/18da0fff-…/`), по sha256 и записани от
   архива в `ops.raw_file`; инструментът само ги чете и не вика data.egov.bg;
2. **приемна зона** (`zakoni_src`): таблица за всеки вид запис, с формата на източника. Всяко прието четене на ресурс е
   партида (`ops.load`) през общия модул `ingest/pipeline.py`: същото съдържание не пише нищо, по-малък отговор чака второ
   четене поне ден по-късно, всяка разлика е ред в `ops.change_log`, поле по поле. Пази се само последното прието четене на
   ресурс; кога записът е видян за пръв път и кога е променен, се пренася от четене на четене;
3. **чисти таблици** (`zakoni`): актове, консултации (с община по `core.municipality`), стратегии и договори с ключа на
   източника (`pris_id`, номер `-K`), срок в дни, индикатор за кратък срок, връзки между набори; ред без ключ отива в
   `zakoni.unmatched`. Строят се цели от приемната зона в една транзакция;
4. правила (`db/checks.toml`): сверки на броя на всеки файл, ключове, дати, индикаторът, дял без община; резултатите са в
   `ops.check_result`;
5. **слой за показване** (`pub_zakoni`): страниците, CSV и JSON четат само него и `pub` (общините). Сменя се само с
   публикуване, след като всички задължителни правила минат; всеки отговор казва версията си (`X-Publication`).

Не се пазят имена на коментиращи, лица за контакт, имейл адреси и имена на физически лица в договорите.

## Стъпки

```bash
python -m ingest.run --step migrate     # схемите и регистрите (основата на danni трябва да е там)
python -m ingest.run --step build       # архив -> приемна зона -> сверки -> чисти таблици -> правила -> публикуване
python -m ingest.run --step check       # чистите таблици наново от приемната зона, правилата, публикуването
python -m ingest.run --step freshness   # какво е закъсняло, задържано или счупено
python -m ingest.run --step replay      # преминаването: файловете, от които е строена старата база, през същия парсер
python -m ingest.run --step parity      # преминаването: старата база срещу общата
```

`build` разбира файл наново само когато архивът има нов (`--force`: винаги). ПРИС е 190 MB и около 330 MB в паметта.

`ZAKONI_DSN` (по подразбиране `dbname=prozrachnost`), `ZAKONI_ARCHIVE` (архивът на Наблюдател), `ZAKONI_DATA`,
`ZAKONI_OLD_DSN` (старата база `zakoni`, само за `replay` и `parity`).

Разписание (UTC, общият workflow „Прозрачност“): `build` всеки ден в 04:30, свежест в 09:20 и 21:20. Тихо, когато всичко е наред.

## Тестове

```bash
pip install -r requirements.txt httpx2
python -m pytest -q                                   # парсерите и стрийминга (без база)
ZAKONI_TEST_DSN=dbname=zakoni_test python -m pytest -q   # и базата, страниците (отделна база; името трябва да съдържа test)
ZAKONI_TEST_DSN=dbname=zakoni_test python tests/mutations.py   # всяко правило, което пази данните, се чупи нарочно
```

Тестовете с база строят основата от съседната папка `tools/danni` (миграциите и местата от истинския архив на ЕКАТТЕ), после
таблиците на Закони. Фикстурите в `tests/fixtures/egov/` са истински записи от файловете на архива от 02.10.2026, съкратени;
личните полета са заменени.
