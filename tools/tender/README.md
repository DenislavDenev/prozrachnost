# Тендер

Независим портал за обществените поръчки в България: **tender.denev.work** (вътрешна мрежа и
tailnet). Договорите са вързани с фирми, фирмите с лица, лицата с другите им фирми. Всяка връзка
има тип, период и източник; сумите се броят веднъж. Правилата са в
[`docs/methodology.md`](docs/methodology.md).

## Какво има

| Страница | Какво показва |
|---|---|
| `/` | обобщение по години, дял на договорите с една оферта, процедури, сектори, най-големите възложители и изпълнители |
| `/companies/<ключ>` | договори по години, индикатори и тагове, мрежа от свързани лица и дружества, лицата във времето, конкуренция, възложители |
| `/persons/<id>` | роли във времето, дърво и граф на връзките, договорите на свързаните дружества в трите режима на броене, потвърдени снимка и статии |
| `/buyers/<ЕИК>` | договори по години, изпълнители, процедури, дял с една оферта |
| `/contracts/<id>`, `/tenders/<УНП>` | всички публикувани полета на записа, описание и разширени данни от OCDS, история на публикациите, анекси, обединения, подизпълнители, източник (файл и sha256) |
| `/buyers`, `/companies`, `/persons` | всички възложители, фирми и лица; филтри и подреждане по всяка колона |
| `/tenders`, `/contracts` | всички поръчки и договори; филтри (предмет, страна, процедура, сектор, състояние) и период (от/до или 30/60/365 дни) |
| `/map` | карта на 265-те общини: стойност, брой договори и дял с една оферта по общината на възложителя, за период; възложители и изпълнители на избраната община |
| `/procedures`, `/sectors` | договорите по вид процедура и по сектор (CPV) за избран период, с дял на една оферта |
| `/search` | търсене по име, ЕИК, УНП; латиница намира кирилица |
| `/sources` | докъде стигат данните и какво още не е прочетено |
| `/admin/review` | ръчно потвърждение на кандидатите за публични фигури и статии (HTTP Basic) |

Списъците се подреждат с клик на заглавието на колона (▲ възходящо, ▼ низходящо; параметри `sort`
и `dir`). Правилата за броене са в `docs/methodology.md`; отделна страница за методологията в сайта
няма (по-късно ще има „Как работи“).

Връзките на фирма или лице се показват като **дърво** (`/lineage.json`): обектът е най-горе, под
него всяко свързано лице или дружество, и всеки клон се отваря до последната връзка („Разгъни
всичко“ отваря до 400 връзки). Графът остава като втори изглед.

CSV на договорите на фирма и възложител, JSON на договор (`/contracts/<id>.json`), мрежата като `/network.json`.

## Как работи

```
storage.eop.bg (дневни JSON)  ─► ingest/eop.py ─► data/raw/eop/<ден>/
                                          │
Търговски регистър (партиди) ─► ingest/tr_worker.py ─► tr.* (опашка, партиди, роли, лица)
                                          │
        ingest/normalize.py + db/derive/*.sql ─► schema stage ─► (publish) ─► schema live ─► app/
```

- **Постоянно състояние**: `ops.*` (изпълнения, файлове, курсове), `tr.*` (регистър), `ed.*` (ръчни
  тагове, кандидати и решения). Миграции в `db/migrations/`.
- **Производно**: всичко в `live` се изгражда наново от суровите файлове и `tr.*` в `stage` и се
  подменя атомарно само след успешен цикъл (`ingest/build.py`).
- **Ключалки**: всяка „лента“ (build, tr, enrich, seed) има своя advisory lock; застъпено пускане
  се отчита като *skipped*.

## Инфраструктура

- **CT 118 `tender`** на Proxmox, `192.168.1.68`, Debian 13, Postgres 17.
  Данните са в `/tank/data/projects/tender` (в контейнера `/opt/tender`).
  - `/opt/tender/app`: работното копие за внедряване;
  - `/opt/tender/data`: `raw/eop`, `raw/tr`, `pg`, `backups` (не са в git).
- **Уеб**: `tender-web.service` (uvicorn :8000) → NPM (CT 109) → `https://tender.denev.work`,
  CNAME в pihole (CT 103).
- **Разписание**: n8n workflow **Tender** (`nFa93aNfs7kmkz5U`) пуска `deploy/ops.sh` по SSH.
  Часовете са в UTC:

  | Клон | Кога | Какво |
  |---|---|---|
  | build | 07:30 дневно | ЕОП → fx → normalize → derive → publish → нови ЕИК в опашката |
  | tr-read | :05 всеки час 06–23 | четене на партиди; когато опашката е празна, търсене по име (тихо при успех) |
  | tr-changes | 05:55 дневно | дневният списък с промени на портала на ТР (D+1 и D+14) |
  | tr-names | :05 всеки час 00–05 | търсене по име: други фирми на известни лица и фирми, в които известна фирма има роля |
  | backup | 02:30 дневно | `pg_dump` (пази 7) + копие в `gs://BACKUP-BUCKET/tender-backups/` (пази 14) |
  | restore-check | 03:30 на 1-во число | възстановяване в `tender_restore_check` и сверка |
  | export | 03:00 дневно | експорт на workflow-а към клона `ops/exports` |
  | sigma-diff | понеделник 06:30 | промени ли се файловете на СИГМА, от които е пренесен парсерът |
  | Deploy (manual) | ръчно | `deploy/deploy.sh main` |

  Успехите отиват като карта в `#cronos`, грешките през `ops/error-notify-discord`.

## Внедряване

```bash
git push origin main
ssh root@192.168.1.68 'bash /opt/tender/app/deploy/deploy.sh main'
```

`deploy.sh` взема една версия, пази дъмп преди миграция, прилага миграциите в транзакция и спира
при грешка, рестартира и проверява `/healthz`; при неуспех връща кода (и базата, ако е имало
миграция).

## Тестове

```bash
pytest tests/test_units.py
```

```bash
TENDER_TEST_DSN=dbname=tender_test pytest tests/test_integration.py
```

Интеграционните тестове изтриват базата от `TENDER_TEST_DSN`. Покриват бивш собственик и договор
след излизането му, верига без едновременно активни ребра, еднакви имена, `BirthDate`, цикъл в
собствеността, един договор по два пътя, обединение, прозореца на индикаторите и търсене на латиница.
